# MuseDock v0.18 更新說明

**一句話：介面沒變。這版是保險——以後帳號清單不會再被一聲不響地蓋掉，出問題也有日誌可查。**

---

## 一、帳號清單不會再被清空

以前有一種情況會讓所有帳號一起消失：`accounts.json` 檔案還在，但內容讀不懂（例如被別的工具改壞、
或未來版本的格式變化）。程式會當成「第一次啟動」，寫入兩個空白帳號把原檔蓋掉。

**現在**：讀不懂就備份、轉成唯讀、跳出提示，一個字都不寫。

| | 以前 | 現在 |
|---|---|---|
| 檔案讀不懂 | 蓋成兩張空白卡片，帳號全消失 | 原檔備份為 `accounts.broken-時間.json`，什麼都不寫 |
| 這期間改名字、匯入、刪帳號 | 看起來成功，實際蓋掉原資料 | 一律拒絕，狀態列顯示 `⚠︎ 資料檔毀損，本次不寫入` |
| 重新啟動 | 帳號回不來了 | 檔案修好或移走就恢復，備份一直留著 |

這是那種「一年不會遇到一次，遇到一次就夠痛」的問題，所以值得先修。

---

## 二、出問題時有日誌可以看

以前從 Dock 或 Finder 開 MuseDock，程式內部所有診斷訊息都直接丟掉——只有從終端機啟動才看得到。
所以每次排查「怎麼又貼不上了」，都得請你重現一次，而你遇到的場景往往重現不出來。

現在一律寫進：

```
~/Library/Logs/MuseDock.log
```

檔案超過 4MB 會自動輪替，只留兩份，不會佔空間。下次回報問題時，把這個檔案給我，比描述十分鐘有用。

> 想自己看一眼：Finder → 前往 → 前往檔案夾 → 貼上 `~/Library/Logs` → 找 `MuseDock.log`。
> 或在終端機 `tail -50 ~/Library/Logs/MuseDock.log` 看最後 50 行。

## 三、兩個新指令

升級和回滾現在對稱了——回滾早就有腳本，升級卻還是手打三行，正是漏步驟的地方。

```bash
./tools/update.sh        # 一鍵升級：拉最新 → 結束舊的 → 重建 → 重開
./tools/update.sh -n     # 只看它打算做什麼，不動任何東西
```

它會先擋下有未提交改動的工作區，`pkill` 之後也會等鎖真的釋放才重開——這兩步漏掉就會出現
「更新沒生效」的假象。

發版也收成一行（這條主要是給開發用的）：

```bash
./tools/release.sh 0.19                  # 改版本號 → 建置 → commit → tag → Release
./tools/release.sh 0.19 --test           # 發版前先跑 16 秒鍵盤自測
```

## 四、升級

```bash
./tools/update.sh
```

`accounts.json` 格式沒變，**不需要重新登入**，頭像快取也不用重抓。

想退回上一版：

```bash
./tools/rollback.sh          # 回到 v0.17
./tools/rollback.sh main     # 後悔了，回到最新
```

## 五、這版沒做的事（先講清楚，免得以為是 bug）

- **熱鍵還是不能自訂**：固定 `⇧⌘1–9`，與別的 App 衝突時只能改用「帳號」選單或側邊欄卡片。
- **匯入前不會先提醒重複**：要等匯入完才標 ⚠︎。
- **記憶體不會依壓力自動調整**：仍是「閒置 10 分鐘釋放」這一條規則。
- **介面完全沒動**：這版所有改動都在看不到的地方。

四件都列在待辦裡，不是漏掉。完整技術說明見 [`CHANGELOG-v0.18.md`](CHANGELOG-v0.18.md)。
